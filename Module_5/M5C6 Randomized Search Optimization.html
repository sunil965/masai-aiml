The Situation

Tuning a Random Forest to predict clinic no-shows — over three hyperparameters at once.

A clinic wants to predict which booked appointments are likely to be no-shows, using a Random Forest. There are three hyperparameters worth tuning: how many trees to grow, how deep each is allowed to go, and how many patients a leaf must contain. Give each one a short list of candidate values, and testing every single combination — the approach you'd reach for by default — turns out to mean training and cross-validating 240 separate models before you even see a result.

The Cost of Being Exhaustive

Three hyperparameters, a handful of values each — and the grid explodes

3 values × 4 values × 4 values  =  48 configurations  ×  5-fold CV  =  240 model fits

Every additional hyperparameter, or every extra candidate value added to an existing one, doesn't add to this number — it multiplies it. Testing every combination is guaranteed to find the best configuration within the grid, but the grid itself can become expensive to search well before the model itself becomes expensive to train.

Randomized Search

Instead of every combination, sample a fixed number of random ones

Grid Search — tests everything

Randomized Search — samples a subset

Each cell is one hyperparameter configuration. Randomized Search picks a set number of random cells (you choose how many — n_iter) and only evaluates those, instead of every cell in the grid.

Worked Example

Grid Search vs. Randomized Search, same data, same hyperparameters

Configurations triedTotal model fitsBest CV scoreTest accuracy
Grid Search48 (all of them)2400.6830.56
Randomized Search12 (n_iter=12)600.6800.57

Sampling just 12 of the 48 possible configurations — a quarter of the work — landed a CV score within 0.003 of the exhaustive search, and matched (in this case, even slightly beat) it on held-out test accuracy. The extra 36 configurations Grid Search checked bought essentially nothing.

Comparing Tuning Techniques

Which one earns its cost depends on how big the search space is

SMALL SEARCH SPACE

Prefer Grid Search

A handful of hyperparameters with a few values each — a few dozen configurations is cheap enough to just check all of them, and you get a guaranteed-best-in-grid answer.

LARGE SEARCH SPACE

Prefer Randomized Search

Many hyperparameters, wide ranges of values, or slow-to-train models — exhaustive search becomes impractical well before it becomes impossible, and sampling finds a near-best answer for a fraction of the cost.

Peak performance isn't only about which single configuration scores highest — it's also about finding a genuinely good one within the time and compute you actually have.
