The Situation

A loan-approval model scores 84% accuracy on a test split. Is that number trustworthy?

You trained a model to predict whether a loan should be approved, split your data once into training and test sets, and got 84% accuracy. That single number is about to go in a report, maybe influence a real deployment decision. But it came from one particular way of splitting the data — and nothing guarantees that split was representative.

This session is about not trusting a single split, and building a validation number you can actually stand behind.

The Problem with a Single Split

Same model, same data, six different splits

Nothing else changed here except which rows randomly landed in the test set:

65% accuracy90% accuracy

Six single splits of the exact same model on the exact same data produced accuracies of 75%, 90%, 70%, 85%, 65%, and 80% — a 25-point swing. Reporting just one of these numbers means reporting whichever split you happened to get.

Implementing k-Fold Cross-Validation

Every row gets to be in the test set exactly once

Split the data into k equal folds. Train k times, each time holding out a different fold as the test set and training on the rest. Every data point is tested on exactly once, across the k rounds — and you get k separate accuracy scores instead of one.

The five fold scores still vary — cross-validation doesn't eliminate variability, real data is genuinely uneven. What it gives you is the full picture instead of one sample from it: a mean of 0.788 with a standard deviation of 0.094, instead of a single, unqualified “84%.”

Comparing Models Using Cross-Validated Metrics

Which model is actually better?

0.700 ± 0.073

Both models were scored with the same 5-fold split. LogisticRegression wins on mean accuracy — and because both numbers come from cross-validation rather than one split each, this comparison is far less likely to be an artifact of which rows happened to land in which set.
