The Situation

A model predicting whether a user will click an ad, left on its defaults, quietly overfits.

Trained with every default setting, a decision tree grows itself out to depth 10 — deep enough to memorize quirks of the training clicks that won't repeat for a new user. On held-out data it gets only 66.7% accuracy. Somewhere in this tree's settings — how deep it's allowed to grow, how many examples a leaf needs before it's allowed to exist — is a better configuration. The question is how to find it without just guessing.

Hyperparameters

Settings you choose before training, not values the model learns

A model's ordinary parameters (like which feature a tree splits on) are learned automatically from the training data. Hyperparameters are different — they're configuration choices you make beforehand, like how deep a tree is allowed to grow, or how many examples a leaf must contain. The model never learns these on its own; you have to set them, and the setting you pick changes how well the model performs.

max_depth, min_samples_leaf, n_estimators, learning_rate  →  all hyperparameters
Grid Search

Try every combination, score each one properly, keep the winner

STEP 1

List candidate values

For each hyperparameter, choose a short list of values worth trying — e.g. max_depth of 2, 4, or 6.

STEP 2

Form the grid

Every combination across all the lists becomes one candidate configuration to test.

STEP 3

Cross-validate each

Score every configuration with cross-validation, not a single split, then keep whichever scored highest.

“Grid” describes the shape of the search: two hyperparameters with 3 candidate values each form a 3×3 grid of 9 configurations to test.
