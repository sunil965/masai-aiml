Ensemble Learning:
Random Forests

One decision tree is opinionated and a little unreliable. A hundred slightly-different decision trees, voting together, are neither.

The Situation

An HR team trains a decision tree to predict employee attrition — and doesn't trust it.

The tree predicts which employees are likely to leave, using tenure, satisfaction scores, overtime, and salary standing. It looks fine — until someone retrains it on a slightly different sample of the same employee data, and the predictions shift noticeably. A single decision tree tends to be sensitive: change the training rows a little, and the tree it builds can change a lot.

A Random Forest fixes this by not relying on just one tree's opinion.

Bootstrap Aggregating (Bagging)

Each tree trains on its own random resample of the data

From the original employees, a Random Forest draws a bootstrap sample for each tree: the same number of rows, chosen randomly with replacement. Some employees get picked more than once; others don't get picked at all for that particular tree.

One real bootstrap draw from 6 employees (A–F): the sample used was [A, F, A, D, C, D] — A and D each appear twice, B and E never appear. Every tree in the forest gets a different draw like this, so every tree ends up trained on slightly different data.

Each tree makes its own prediction; the forest's final answer is a majority vote (classification) or an average (regression) across all the trees. This is what “aggregating” means.

Feature Randomness

Every split also only considers a random subset of features

Bootstrap sampling alone isn't quite enough — if one feature (say, satisfaction score) is by far the strongest predictor, nearly every tree would still choose it for its very first split, making the trees end up similar anyway. A Random Forest adds a second layer of randomness: at each individual split, only a random subset of the features is even considered as candidates — not the full feature list.

at each split  →  consider only √(number of features) features, chosen at random

This forces trees to sometimes split on a weaker-but-still-useful feature instead of always defaulting to the strongest one — making the trees genuinely different from each other, not just trained on slightly different rows of the same obvious pattern.

Worked Example

One tree vs. a forest of 100, across 6 different splits

Single Decision Tree — mean 0.719, range 0.267
Random Forest (100 trees) — mean 0.819, range 0.111

Same employee data, same six train/test splits, nothing else changed. The single tree's accuracy swings from 0.62 to 0.89 depending on the split — a 27-point range. The forest is both more accurate on average and far more stable: its worst split (0.78) still beats the single tree's average.
